Build Models

This stage focuses on developing the models that power AI applications on IBM LinuxONE. Activities may include building traditional machine learning or deep learning models, or selecting and serving a pre-built foundation model. IBM LinuxONE supports the popular open-source tools and frameworks AI practitioners already use, with hardware acceleration available through the Telum II on-chip AI accelerator and IBM Spyre Accelerator cards for supported workloads.

What happens at this stage?

Build traditional ML models

Train classification, regression, forecasting, or recommendation models on structured enterprise data using IBM Z Accelerated for Snap ML, watsonx.ai, or standard Python ML libraries on IBM LinuxONE.

Build deep learning models

Develop neural networks for computer vision, NLP, or other unstructured data workloads using IBM Z Accelerated for TensorFlow or IBM Z Accelerated for PyTorch — both optimized for IBM LinuxONE hardware and available as container images.

Use pre-built large language models

Source a pre-existing LLM from Hugging Face, IBM, or a commercial provider and serve it directly on IBM LinuxONE — no training required. Leverage Spyre Accelerator cards for generative AI workloads.

Export for deployment

Save your model in a portable format — PMML for traditional ML, ONNX for deep learning or encoder LLMs — then compile with the IBM Z Deep Learning Compiler (zDLC) to leverage Telum II acceleration at inference time.

Who is this stage for?

Model development is typically led by Data Scientists, with ML Engineers supporting training pipelines, automation, and operationalization. IT Architects and Application Architects help evaluate platforms, frameworks, and deployment requirements. Business stakeholders provide domain expertise and define success criteria such as model accuracy thresholds and latency requirements.

Where to Start

Your starting point depends on the type of model you're building. The three paths below reflect how IBM LinuxONE typically supports the spectrum of model types.

Building Traditional Machine Learning Models

You are working with structured or tabular data and need models such as classification, regression, or forecasting systems. Models can be trained off-platform using your existing tools and deployed to IBM LinuxONE, or built directly on-platform.

You need to train classical ML models on IBM LinuxONE using a library purpose-built and optimized for the platform.

→ Use IBM Z Accelerated for Snap ML. Snap ML is the primary training technology for traditional ML on IBM LinuxONE, supporting generalized linear models, tree-based models, and gradient boosting. It is fast, efficient, accurate, and scales to large volumes of data. Decision tree ensemble inference is optimized on the Telum II on-chip AI accelerator. Snap ML is available as a container image via the IBM Container Registry (ICR) and is included in the AI Toolkit for IBM Z and IBM LinuxONE.

Common approach: Prepare features with Snap ML preprocessing transformers → Train with Snap ML → Export to PMML → Deploy and serve on IBM LinuxONE.

Your team prefers standard Python workflows and wants to train models using familiar libraries — scikit-learn, XGBoost, pandas, NumPy — in Jupyter Notebooks on IBM LinuxONE.

→ Use standard Python ML libraries on IBM LinuxONE. Because IBM LinuxONE runs a full Linux environment, there is no special toolkit required — scikit-learn, XGBoost, LightGBM, and other Python ML frameworks install and run natively. This makes it easy for teams already using these tools to train on-platform without changing their workflows.

Common approach: Explore data in Jupyter Notebooks → Train with scikit-learn or XGBoost → Export to PMML or ONNX → Deploy on IBM LinuxONE.

You want a managed platform for model development, experiment tracking, and automated training pipelines for traditional ML on IBM LinuxONE.

→ Use watsonx.ai or Red Hat OpenShift AI. watsonx.ai on IBM LinuxONE (via IBM Software Hub) provides a Jupyter-based ML development environment with AutoML and experiment tracking for building traditional ML models. Red Hat OpenShift AI on IBM LinuxONE provides shared data science workbenches and Kubeflow-based automated training pipelines — so teams can develop, iterate, and promote models collaboratively within a Kubernetes-native environment.

Common approach: Develop and train ML models in watsonx.ai or Red Hat OpenShift AI Jupyter workbenches → Track experiments and manage training runs → Export trained model for deployment on IBM LinuxONE.

Building Deep Learning Models

You need to develop neural networks for computer vision, natural language processing, or other unstructured data workloads — off-platform or on-platform. Deep learning models are trained with IBM Z Accelerated for TensorFlow or IBM Z Accelerated for PyTorch and typically exported to ONNX for deployment on IBM LinuxONE.

You are building deep learning models and want to train and deploy natively on IBM LinuxONE, leveraging Telum II hardware acceleration.

→ Use IBM Z Accelerated for TensorFlow or IBM Z Accelerated for PyTorch. Both frameworks are optimized for IBM LinuxONE hardware and exploit the Integrated Accelerator for AI on Telum II for inference. IBM Z Accelerated for PyTorch also supports Transformer-based architectures including encoder-based models. Both are available as container images via the IBM Container Registry (ICR) (part of the AI Toolkit for IBM Z and IBM LinuxONE).

Common approach: Prepare data → Train with IBM Z Accelerated for TensorFlow or IBM Z Accelerated for PyTorch → Deploy directly via IBM Z Accelerated for Triton Inference Server or Red Hat OpenShift AI on IBM LinuxONE.

You have trained a deep learning model in any framework and want to convert it to ONNX and deploy it on IBM LinuxONE with Telum II acceleration.

→ Convert your model to ONNX format using your framework of choice, then compile with the IBM Z Deep Learning Compiler (zDLC) to leverage the Integrated Accelerator for AI on Telum II at inference time. The zDLC supports deep learning models and encoder LLMs, and produces shared library files embeddable in applications independent of the original framework. The zDLC is available as a container via the IBM Container Registry (ICR).

Common approach: Train with any framework (TensorFlow, PyTorch, Keras, or other) → Export to ONNX → Compile with zDLC → Deploy via IBM Z Accelerated for Triton Inference Server or Red Hat OpenShift AI on IBM LinuxONE.

You have trained a model using any framework on any platform and want to convert it to a portable format and deploy it on IBM LinuxONE.

→ Export your model to PMML (traditional ML) or ONNX (deep learning or encoder LLMs) and deploy it on IBM LinuxONE. PMML and ONNX are portable interchange formats supported by IBM LinuxONE serving tools — no dependency on the original training framework at inference time. For deep learning and encoder LLMs, compile the ONNX model with the IBM Z Deep Learning Compiler (zDLC) to leverage Telum II acceleration.

Common approach: Train with any framework off-platform → Export to PMML or ONNX → (For deep learning) Compile with zDLC → Deploy via AI Toolkit containers or Red Hat OpenShift AI on IBM LinuxONE.

Multiple teams need shared workspaces, automated pipelines, and model lifecycle management for deep learning on IBM LinuxONE.

→ Use Red Hat OpenShift AI. Provides data science workbenches, Kubeflow pipelines, and model lifecycle management on IBM LinuxONE via Red Hat OpenShift. Teams already using OpenShift AI on other platforms can bring their existing skills and workflows directly to IBM LinuxONE — the OpenShift experience is consistent across environments.

Common approach: Create shared projects → Train IBM Z Accelerated for TensorFlow or IBM Z Accelerated for PyTorch models → Promote through OpenShift pipelines → Deploy on IBM LinuxONE.

Using Pre-built Large Language Models

Large language models can be sourced from IBM, open source communities, or commercial providers and served directly on IBM LinuxONE without customization or training from scratch. The IBM Spyre Accelerator cards provide dedicated Gen AI-ready cores purpose-built for LLM inference workloads.

Your use case is well-served by a general-purpose LLM sourced from Hugging Face, IBM Granite, or another model provider — no training required.

→ Use Red Hat AI Inference Server (vLLM-based, optimized for Spyre-accelerated decoder LLMs) or Red Hat OpenShift AI (for broader model management, monitoring, and serving) to serve a pre-built LLM on IBM LinuxONE. Supported models include Granite, Llama, and others.

Note: Red Hat AI Inference Server runs standalone and does not require Red Hat OpenShift. Red Hat OpenShift AI is the better fit if your organization already has an OpenShift container strategy on IBM LinuxONE.

Common approach: Select a model from Hugging Face or IBM model repository → Serve via Red Hat AI Inference Server or Red Hat OpenShift AI on IBM LinuxONE → Integrate with your application via REST API.
