Build & Train Models

This stage focuses on developing the models that power AI applications on IBM LinuxONE. Activities may include building machine learning or deep learning models, fine-tuning, or selecting and serving pre-built foundation models. IBM LinuxONE supports the popular open-source tools and frameworks AI practitioners already use, with hardware acceleration available through the Telum II on-chip AI accelerator and IBM Spyre Accelerator cards for supported workloads.

What happens at this stage?

Build Machine Learning models

Train classification, regression, forecasting, or recommendation models on structured enterprise data using IBM Z Accelerated SnapML, watsonx.ai, or standard Python ML libraries on IBM LinuxONE.

Build deep learning models

Develop neural networks for computer vision, NLP, or other unstructured data workloads using IBM Z Accelerated for TensorFlow or IBM Z Accelerated for PyTorch — both optimized for IBM LinuxONE hardware and available as container images through the AI Toolkit for IBM LinuxONE.

Build, fine-tune, or use pre-built LLMs

1) Use pre-built LLMs as-is from IBM or open source, 2) fine-tune pre-built LLMs on proprietary enterprise data, or 3) build and train bespoke custom LLMs. Leverage Spyre Accelerator cards for generative AI workloads.

Export for deployment

Save your model in a portable format — PMML for machine learning models, ONNX for deep learning or encoder LLMs — then compile with the IBM Z Deep Learning Compiler (zDLC) to leverage Telum II acceleration at inference time.

Who is this stage for?

Model development is typically led by Data Scientists, with ML Engineers supporting training pipelines, automation, and operationalization. IT Architects and Application Architects help evaluate platforms, frameworks, and deployment requirements. Business stakeholders provide domain expertise and define success criteria such as model accuracy thresholds and latency requirements.

Where to Start

Your starting point depends on the type of model you're building. The three paths below reflect how IBM LinuxONE typically supports the spectrum of model types.

Building Machine Learning Models

You are working with structured or tabular data and need models such as classification, regression, or forecasting systems. Models can be trained off-platform using your existing tools and deployed to IBM LinuxONE, or built directly on-platform.

You need to train classical ML models on IBM LinuxONE using a library purpose-built and optimized for the platform.

→ Use IBM Z Accelerated SnapML. Snap ML is the primary training technology for machine learning on IBM LinuxONE, supporting generalized linear models, tree-based models, and gradient boosting. It is fast, efficient, accurate, and scales to large volumes of data. Decision tree ensemble inference is optimized on the Telum II on-chip AI accelerator. Snap ML is available as a container image via the IBM Container Registry (ICR) and is included in the AI Toolkit for IBM LinuxONE.

Common approach: Prepare features with Snap ML preprocessing transformers → Train with Snap ML → Export to PMML → Deploy and serve on IBM LinuxONE.

Your team prefers standard Python workflows and wants to train models using familiar libraries — scikit-learn, XGBoost, pandas, NumPy — in Jupyter Notebooks on IBM LinuxONE.

→ Use standard Python ML libraries on IBM LinuxONE. Because IBM LinuxONE runs a full Linux environment, there is no special toolkit required — scikit-learn, XGBoost, LightGBM, and other Python ML frameworks install and run natively. This makes it easy for teams already using these tools to train on-platform without changing their workflows.

Common approach: Explore data in Jupyter Notebooks → Train with scikit-learn or XGBoost → Export to PMML or ONNX → Deploy on IBM LinuxONE.

Building Deep Learning Models

You need to develop neural networks for computer vision, natural language processing, or other unstructured data workloads — off-platform or on-platform. Deep learning models are trained with IBM Z Accelerated for TensorFlow or IBM Z Accelerated for PyTorch and typically exported to ONNX for deployment on IBM LinuxONE.

You are building deep learning models and want to train and deploy natively on IBM LinuxONE, leveraging Telum II hardware acceleration.

→ Use IBM Z Accelerated for TensorFlow or IBM Z Accelerated for PyTorch. Both frameworks are optimized for IBM LinuxONE hardware and exploit the Integrated Accelerator for AI on Telum II for inference. IBM Z Accelerated for PyTorch also supports Transformer-based architectures including encoder-based models. Both are available as container images via the IBM Container Registry (ICR) (part of the AI Toolkit for IBM LinuxONE).

Common approach: Prepare data → Train with IBM Z Accelerated for TensorFlow or IBM Z Accelerated for PyTorch → Deploy directly via IBM Z Accelerated for Triton Inference Server or Red Hat OpenShift AI on IBM LinuxONE.

Multiple teams need shared workspaces, automated pipelines, and model lifecycle management for deep learning on IBM LinuxONE.

→ Use Red Hat OpenShift AI. Provides data science workbenches, Kubeflow pipelines, and model lifecycle management on IBM LinuxONE via Red Hat OpenShift. Teams already using OpenShift AI on other platforms can bring their existing skills and workflows directly to IBM LinuxONE — the OpenShift experience is consistent across environments.

Common approach: Create shared projects → Train IBM Z Accelerated for TensorFlow or IBM Z Accelerated for PyTorch models → Promote through OpenShift pipelines → Deploy on IBM LinuxONE.

Using Large Language Models (LLMs) & Foundation Models

When working with foundation models on IBM LinuxONE, there are three paths: use a pre-built LLM as-is, fine-tune a pre-built LLM on your data, or build and train a custom SLM or encoder. If your use case is satisfied by a standard foundation model without any modification, skip this stage — go directly to Deploy Models. The two paths below require work at this stage.

Adapt a foundation model to organizational domain knowledge, specialized vocabularies, or task-specific schemas while retaining core model capabilities.

→ Fine-tune a foundation model on your domain data. Fine-tuning updates model weights on a curated dataset (e.g., internal documentation, domain-specific terminology, or proprietary transaction records), achieving domain alignment while keeping sensitive enterprise training data on-premises.

Common approach: Prepare domain datasets on IBM LinuxONE → Execute tuning pipelines via Red Hat OpenShift AI → Merge weights or export LoRA adapters → Deploy to Red Hat AI Inference Server on IBM LinuxONE.

You need a compact, task-specific model trained from scratch — such as a domain encoder or small transformer.

→ Train custom architectures using IBM Z Accelerated for PyTorch or Red Hat OpenShift AI pipelines natively on IBM LinuxONE. Once trained, export to ONNX for deployment — see Deploy Models for the compilation and serving steps.

Common approach: Train encoder/SLM architecture using IBM Z Accelerated for PyTorch → Export to ONNX → proceed to Deploy Models.
