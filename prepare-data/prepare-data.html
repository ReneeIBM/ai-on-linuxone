Prepare Data

Before a model can be trained, your data needs to be in the right shape — cleaned, transformed, and structured in a way the model can learn from. For IBM Z teams, this stage has a distinct advantage: your most valuable enterprise data already lives here, in Db2, IMS, VSAM, and transactional systems. You don't need to move it to prepare it.

This page helps you understand what data preparation looks like on IBM Z, which tools apply to your situation, and how to move forward whether you're building your first proof of concept or preparing a production pipeline.

What happens at this stage?

Access & Connect

Connect to enterprise data sources — Db2, IMS, VSAM, flat files — without moving data off-platform.

Cleanse & Validate

Handle missing values, inconsistent formats, duplicates, and outliers so your model trains on reliable data.

Transform & Engineer Features

Aggregate, normalize, encode, and derive new features that give the model meaningful signals to learn from.

Build Pipelines

Automate repeatable preparation steps so data flows consistently from source to model training — and again at inference time.

Who is this stage for?

Data preparation is primarily owned by Data Engineers and Data Scientists, often working together. Data Owners and Line of Business stakeholders are involved in defining what data is relevant and what the expected values look like. If you're a data scientist who works end-to-end on smaller projects, this stage is still yours — the tools below work for both pipelines and notebooks.

Where to Start

Your starting point depends on where your data resides, how much preparation is required, and how your team prefers to work.

Starting a POC or Demo

You don't have access to production data yet, or you want to move quickly without data privacy concerns.

→ Start with IBM Synthetic Data Sets. Pre-built, realistic datasets help you build, test, and validate models without waiting for production data access.

Common approach: Use synthetic data to develop and validate a model, then retrain with production data when it becomes available.

Working with Db2 Data on z/OS

Your data already resides in Db2 for z/OS and you want to explore patterns, relationships, or features without building a separate data pipeline.

→ Use IBM SQL Data Insights Pro. Run AI-powered semantic analysis directly against Db2 data while keeping data in place.

Common approach: Perform in-database exploration and feature discovery, then pass selected features into a training workflow.

Building a Production Data Pipeline

You need to process large volumes of enterprise data, perform complex transformations, or create repeatable feature engineering workflows.

→ Use IBM Z Platform for Apache Spark. Spark runs natively on z/OS and supports large-scale data preparation close to enterprise data sources.

Common approach: Build Spark pipelines that cleanse, transform, and enrich data before supplying it to model training frameworks.

Building a Production AI and MLOps Platform

Multiple teams need shared workspaces, automated pipelines, model management, deployment, and governance.

→ Use Red Hat OpenShift AI. Provides data science workbenches, Kubeflow pipelines, model serving, monitoring, and MLOps capabilities on a unified platform.

Common approach: Centralize data preparation, training, deployment, and governance within a shared AI platform.

Preparing Features for Traditional Machine Learning

You already have data but need to transform it into features suitable for machine learning models.

→ Use Snap ML. Snap ML includes data preparation and feature engineering capabilities that support traditional machine learning workflows.

Common approach: Select and transform features, then train classification, regression, or recommendation models using Snap ML.

Preparing Data Outside IBM Z

Your team already uses cloud, data lake, or x86-based tooling for data preparation but plans to deploy AI workloads on IBM Z.

→ Use your existing data preparation tools and export models in portable formats such as ONNX or PMML.

Common approach: Prepare and train externally, then deploy and serve models on IBM Z for low-latency inference alongside enterprise applications.
