Serve Model

Serving is the stage where a deployed model is made available for production use. On IBM LinuxONE, as soon as a model is deployed a scoring endpoint is created — serving and deploying are effectively the same step. This stage focuses on invoking that endpoint from your applications and managing the model in production over time.

The invocation method depends on your runtime: models deployed in IBM Z Accelerated for Triton Inference Server, IBM Z Accelerated Serving for TensorFlow, or Red Hat AI Inference Server are called via REST or gRPC. Invocation happens directly on IBM LinuxONE, close to enterprise data, reducing latency and enabling AI to be embedded into your Linux applications and containerized services.

What happens at this stage?

Integrate the model into your application

The scoring endpoint is created at deploy time — this stage is about wiring it into your business application via REST API or gRPC from your Linux workloads and containerized services on IBM LinuxONE.

Handle production traffic

Configure dynamic batching, concurrency, and throughput settings to handle inference requests at production volume while meeting SLA requirements — up to 450 billion inference requests per day with 99% completing within 1ms on IBM LinuxONE.

Manage model versions

Support model versioning and controlled updates, allowing new model versions to be swapped in, tested, and rolled back with minimal disruption to production workloads.

Infuse AI into applications

Embed inference directly into Linux applications and microservices co-located with enterprise data on IBM LinuxONE — eliminating data movement and minimizing latency for real-time transactional AI.

Who is this stage for?

Serving is typically owned by ML Engineers and Application Architects, with Data Scientists as stakeholders validating that the serving layer produces correct outputs. Line of Business and IT Architects set the SLA and throughput requirements the serving layer should meet.

Where to Start

Your serving method and runtime platform are determined by your model type and where it was deployed. The three subsections below map to those two dimensions.

Invoking Traditional Machine Learning Models

Traditional ML models on IBM LinuxONE are served via containerized runtimes and exposed as REST or gRPC endpoints. Depending on the model type, they may leverage the Telum II on-chip AI accelerator (e.g., gradient boosting and random forest) or run on native CPU (e.g., linear regression). IBM Z Accelerated for Triton Inference Server supports both PMML and ONNX traditional ML models alongside deep learning workloads.

You have a traditional ML model exported to PMML or ONNX and want to serve it as a containerized REST endpoint on IBM LinuxONE.

→ Use IBM Z Accelerated for Triton Inference Server or manage via Red Hat OpenShift AI. IBM Z Accelerated for Triton Inference Server supports PMML and ONNX models alongside deep learning workloads in a single containerized runtime, exposing REST and gRPC endpoints. Red Hat OpenShift AI wraps Triton with MLOps pipeline management and monitoring.

Common approach: Export model to PMML or ONNX → Deploy to IBM Z Accelerated for Triton Inference Server on IBM LinuxONE → Invoke via REST or gRPC from your Linux application.

Invoking Deep Learning Models and Encoder LLMs (Telum II On-Chip Accelerator)

Deep learning models and encoder LLMs targeting the Telum II on-chip AI accelerator are invoked through containerized inference runtimes on IBM LinuxONE. Applications call these models via REST or gRPC endpoints. Encoder LLMs may also choose the Spyre path — see the next subsection.

You need a single inference server that handles ONNX, IBM Z Accelerated for TensorFlow, IBM Z Accelerated for PyTorch, and zDLC-compiled models, running in containers on IBM LinuxONE.

→ Use IBM Z Accelerated for Triton Inference Server. Provides a unified, high-performance runtime for deep learning, encoder LLM, and traditional ML models on IBM LinuxONE. Supports concurrent model execution and dynamic batching to meet strict SLAs. Applications invoke models via REST or gRPC endpoints. Run prediction of customer transactions 3.5× faster by co-locating your application with Snap ML on IBM LinuxONE vs. running prediction remotely on an x86 server.

Common approach: Deploy zDLC-compiled ONNX model to IBM Z Accelerated for Triton Inference Server → Invoke via gRPC or REST from your Linux application on IBM LinuxONE.

Your model is a TensorFlow SavedModel and you want to serve it using the IBM Z Accelerated Serving for TensorFlow runtime.

→ Use IBM Z Accelerated Serving for TensorFlow. A flexible, high-performing serving system optimized for IBM LinuxONE hardware, leveraging Telum II acceleration. Served via HTTP REST or gRPC interfaces. Available as a container image via the IBM Container Registry (ICR).

Common approach: Export IBM Z Accelerated for TensorFlow SavedModel → Deploy to IBM Z Accelerated Serving for TensorFlow on IBM LinuxONE → Invoke via REST or gRPC from your application.

Multiple teams need shared serving infrastructure, monitoring, scaling controls, and pipeline management for deep learning workloads.

→ Use Red Hat OpenShift AI. Red Hat OpenShift AI on IBM LinuxONE manages serving infrastructure for both Telum II and Spyre workloads — the right platform when you need coverage across multiple accelerators, model types, or teams. Includes model serving, monitoring, alerting, and lifecycle management within a Kubernetes-native environment.

Common approach: Deploy model servers (IBM Z Accelerated for Triton Inference Server or IBM Z Accelerated Serving for TensorFlow) through OpenShift AI on IBM LinuxONE → Monitor performance and scale inference workloads from a unified MLOps platform.

You have an encoder LLM (e.g., BERT-style) and want to serve it on the Telum on-chip AI accelerator.

→ Use IBM Z Accelerated for Triton Inference Server or Red Hat OpenShift AI. Encoder LLMs targeting Telum II follow the ONNX → zDLC compilation path: export the model to ONNX, compile with IBM Z Deep Learning Compiler (zDLC), and serve via IBM Z Accelerated for Triton Inference Server or Red Hat OpenShift AI on IBM LinuxONE.

Common approach: Export encoder LLM to ONNX → Compile with zDLC → Deploy to IBM Z Accelerated for Triton Inference Server on IBM LinuxONE → Serve via gRPC or REST endpoint.

Note: Encoder LLMs can also be served on Spyre — see the next subsection. The choice depends on your SLAs and whether you have Spyre available.

Invoking Large Language Models on Spyre

Decoder LLMs always use the IBM Spyre Accelerator. Encoder LLMs may also choose Spyre over Telum depending on Application SLAs and hardware availability. Both Red Hat AI Inference Server and Red Hat OpenShift AI are valid serving paths — no ONNX conversion is required for either. Applications invoke Spyre-accelerated LLMs via REST.

You want Spyre-accelerated LLM inference without the full Red Hat OpenShift AI platform. No ONNX conversion required — LLMs are served natively.

→ Use Red Hat AI Inference Server. The recommended path for LLM inference on Spyre without the OpenShift AI platform. vLLM-based, runs standalone, exposes an OpenAI-compatible REST API, and serves LLMs natively without any ONNX conversion. Supports Granite, Llama, Qwen, DeepSeek, Gemma, Mistral, and other models on IBM LinuxONE Spyre.

Common approach: Source or fine-tune an LLM → Deploy natively via Red Hat AI Inference Server on IBM LinuxONE with Spyre acceleration → Invoke via REST.

You need MLOps pipeline management, monitoring, and model governance around your LLM serving, or a single platform that covers both Telum and Spyre workloads. No ONNX conversion required — LLMs are served natively.

→ Use Red Hat OpenShift AI. Both Red Hat AI Inference Server and Red Hat OpenShift AI are valid paths for LLM inference on Spyre — no ONNX conversion required for either. Choose OpenShift AI when you need the broader platform: MLOps pipelines, model governance, and unified management across Telum II and Spyre workloads on IBM LinuxONE.

Common approach: Manage LLM serving through OpenShift AI using the Red Hat AI Inference Server runtime for Spyre workloads, or IBM Z Accelerated for Triton Inference Server for Telum II workloads — all from a single MLOps platform on IBM LinuxONE.
