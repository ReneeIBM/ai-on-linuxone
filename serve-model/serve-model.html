AI on IBM Z

Serve Model

Serving is the stage where a deployed model becomes accessible to applications and users — exposing predictions via a REST API, a gRPC endpoint, or a native z/OS scoring interface that an application calls in real time. On IBM Z, inference serving is where the performance story becomes concrete: co-locating the serving layer with your transactions and data eliminates network latency and makes in-transaction AI at enterprise scale possible.

IBM Z provides a range of serving options to match the model type, workload pattern, and application environment — from native CICS and IMS scoring inside z/OS to containerized multi-framework servers on Linux on Z to enterprise LLM inference for generative AI workloads.

What happens at this stage?

Expose a scoring endpoint

Make the deployed model accessible via a REST API, gRPC interface, or native z/OS scoring call that applications can invoke for real-time predictions.

Handle production traffic

Configure dynamic batching, concurrency, and throughput settings to serve inference requests at production volume while meeting SLA requirements.

Manage model versions

Support hot model reload and versioned endpoints so you can update or roll back models without downtime.

Infuse AI into applications

Integrate the serving endpoint directly into business applications — CICS transactions, IMS workflows, microservices, or REST-based integrations.

Who is this stage for?

Serving is primarily owned by ML Engineers and Application Architects, with Data Scientists as stakeholders validating that the serving layer produces correct outputs. Line of Business and IT Architects set the SLA and throughput requirements the serving layer must meet.

Where to Start

Your starting point depends on where you want to serve the model, the model formats you need to support, and how you plan to operate inference at scale.

Serving Models Across Multiple Frameworks

You need a single inference platform that supports ONNX, TensorFlow, PyTorch, and other model formats.

→ Start with IBM Z Accelerated for Triton Inference Server. Triton provides a unified serving platform for multiple model types and supports high-performance production inference.

Common approach: Export model → Deploy to Triton → Serve through APIs.

Serving TensorFlow Models

Your model remains in TensorFlow format and you want a dedicated serving solution.

→ Start with IBM Z Accelerated Serving for TensorFlow. TensorFlow Serving provides a production runtime optimized for serving TensorFlow models.

Common approach: Export TensorFlow SavedModel → Deploy to TensorFlow Serving → Expose inference endpoint.

Managing Enterprise AI Inference

Multiple teams require deployment controls, monitoring, scaling, governance, and operational oversight.

→ Start with Red Hat OpenShift AI. OpenShift AI provides the platform layer that manages model serving infrastructure, monitoring, and MLOps operations.

Common approach: Deploy model servers → Monitor performance → Scale inference workloads.

Managing AI Assets Across Serving Environments

You need to manage AI assets, promote approved models, and coordinate deployments across multiple serving platforms.

→ Start with watsonx.ai. watsonx.ai provides model cataloging, asset management, lifecycle controls, and governance integration for AI systems moving into production.

Common approach: Register model → Track versions and approvals → Promote into serving environments such as OpenShift AI, MLz, or inference servers.

Most organizations use watsonx.ai to manage and govern AI assets rather than as the serving runtime itself.

Deploying Models to an Enterprise Inference Runtime

You need a production inference server capable of hosting and serving AI models at scale.

→ Start with Red Hat AI Inference Server. Red Hat AI Inference Server provides model hosting, inference APIs, and scalable serving infrastructure for production AI workloads.

Common approach: Deploy model to Red Hat AI Inference Server → Expose inference endpoints → Scale and monitor workloads.

Organizations often access Red Hat AI Inference Server through broader platforms such as OpenShift AI rather than interacting with it directly.

Centralizing and Optimizing Inference

You need a common gateway for deploying, routing, and optimizing inference workloads across multiple model types.

→ Start with AI Optimizer for IBM Z and LinuxONE. AI Optimizer helps operationalize and route inference workloads while simplifying deployment architectures.

Common approach: Register model → Configure inference routing → Deploy optimized inference services.
