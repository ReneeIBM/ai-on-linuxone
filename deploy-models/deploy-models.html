AI on IBM Z

Deploy Models

After training, most models need to be prepared before they can run efficiently in production on IBM Z. This stage covers both optimization — converting your model into the right format and compiling it for hardware acceleration — and deployment, where your model moves into a production runtime and begins scoring real data.

IBM Z supports multiple paths depending on your model type, your target operating environment, and how you need to integrate AI into your applications.

What happens at this stage?

Convert to a portable format

Export your trained model to ONNX (deep learning) or PMML (traditional ML) — standard interchange formats that work across Z operating systems and deployment tools.

Optimize for IBM Z hardware

Compile and quantize your model using the IBM Z Deep Learning Compiler or AI Optimizer to maximize inference performance on Telum and Spyre acceleration.

Move to production

Deploy your model to a production runtime — on z/OS, Linux on Z, or an OpenShift container environment — co-located with the enterprise data it needs to score.

Configure scoring endpoints

Set up the model to receive inference requests via REST API, CICS/IMS native scoring, batch jobs, or a gRPC serving endpoint.

Who is this stage for?

Optimization and deployment are jointly owned by ML Engineers and IT Architects. The ML Engineer handles model conversion, compilation, and the deployment artifact. The IT Architect owns the infrastructure decisions — operating environment, serving topology, and integration with business applications. Data Scientists are stakeholders who validate that the deployed model performs as expected.

Where to Start

Your path depends on your model type, target environment, and deployment requirements. Use this to find your path:

Deploying a Traditional Machine Learning Model

You have a trained model from Snap ML, scikit-learn, XGBoost, Spark MLlib, or another traditional ML framework.

→ Start with PMML. PMML provides a portable format for many traditional machine learning models and enables deployment without requiring the original training framework.

Common approach: Train a model → Export to PMML → Deploy through AI Optimizer or MLz scoring services.

Deploying a Deep Learning Model

You have a trained neural network and want portable deployment across serving platforms.

→ Start with ONNX. ONNX creates a framework-independent model format that simplifies optimization and deployment across environments.

Common approach: Convert to ONNX → Optimize and deploy for production inference.

Optimizing a Deep Learning Model for IBM Z Hardware

You have a deep learning model in ONNX format and want to maximize inference performance on IBM Z and LinuxONE.

→ Start with IBM Z Deep Learning Compiler (ZDLC). ZDLC generates optimized deployment artifacts that take advantage of IBM Z hardware acceleration.

Common approach: Train model → Convert to ONNX → Optimize with ZDLC → Deploy to a serving platform.

Most users will encounter ZDLC as an optional optimization step after selecting a deployment format such as ONNX.

Deploying Models Trained with TensorFlow

Your model was trained using TensorFlow and is ready to be prepared for production deployment.

→ Start by exporting a TensorFlow SavedModel or converting to ONNX. TensorFlow models can be deployed directly with TensorFlow Serving or converted to ONNX for use across multiple serving platforms.

Common approach: Train with TensorFlow → Export SavedModel or ONNX → Deploy to TensorFlow Serving, Triton, MLz, or OpenShift AI.

TensorFlow is primarily a training framework; deployment choices are typically made after training is complete.

Deploying Models Trained with PyTorch

Your model was trained using PyTorch and you want to deploy it into a production environment.

→ Start by exporting to ONNX. ONNX provides a portable deployment format that integrates with many serving platforms.

Common approach: Train with PyTorch → Convert to ONNX → Deploy to Triton, MLz, or OpenShift AI.

PyTorch is primarily a training framework rather than a deployment technology.

Deploying Models Trained with Snap ML

Your model was trained using Snap ML and is ready for production deployment.

→ Start by exporting to PMML. PMML provides a portable format for many traditional machine learning models.

Common approach: Train with Snap ML → Export PMML → Deploy through MLz or other scoring platforms.

Snap ML is primarily a training technology. Deployment decisions typically begin after exporting the trained model.

Deploying Models Across Multiple Frameworks

You need to serve TensorFlow, PyTorch, ONNX, or other model types from a common inference platform.

→ Use Triton Inference Server. Triton supports multiple framework formats through a single serving environment.

Common approach: Train using your preferred framework → Export model → Deploy through Triton.

Building an Enterprise AI Deployment Platform

Multiple teams require deployment pipelines, model catalogs, monitoring, and operational controls.

→ Use Red Hat OpenShift AI. OpenShift AI provides the MLOps layer that manages model deployment, serving infrastructure, monitoring, and lifecycle operations.

Common approach: Register model → Deploy using Triton or TensorFlow Serving → Monitor and manage through OpenShift AI.

Managing AI Assets Across the Full Lifecycle

You need model governance, catalogs, lifecycle management, and enterprise AI oversight.

→ Use watsonx.ai. watsonx.ai helps manage AI assets and integrates with broader AI lifecycle and governance workflows.

Common approach: Build or import model → Track and manage AI assets → Promote approved models into deployment platforms.
