# AI on IBM Z — Site

A static technical reference site for AI on IBM Z and LinuxONE. Covers hardware acceleration, the full AI lifecycle, products & tools, and solution blueprints. Built as plain HTML/CSS/JS — no framework, no build step.

## Publishing to GitHub Pages

### First-time setup

1. **Create a GitHub repository** (e.g. `your-org/ai-on-z-site`)

2. **Push the `ai-on-z/` folder contents** to the repository root:
   ```bash
   cd ai-on-z
   git init
   git remote add origin https://github.com/your-org/ai-on-z-site.git
   git add .
   git commit -m "Initial publish"
   git push -u origin main
   ```

3. **Enable GitHub Pages** in the repository settings:
   - Go to **Settings → Pages**
   - Under **Source**, select **Deploy from a branch**
   - Set **Branch** to `main`, folder to `/ (root)`
   - Click **Save**

4. GitHub will build and publish the site. The URL will be:
   ```
   https://your-org.github.io/ai-on-z-site/
   ```
   (or a custom domain if configured)

### Using a custom domain

1. In **Settings → Pages → Custom domain**, enter your domain (e.g. `aionz.example.com`)
2. Add a `CNAME` file to the repo root containing just your domain name:
   ```
   aionz.example.com
   ```
3. Configure your DNS provider with a CNAME record pointing to `your-org.github.io`

## Updating content

All pages are plain HTML. To update a page:

1. Open the relevant `.html` file (e.g. `products-tools/ai-platforms.html`)
2. Edit the content inside the `<section class="section" id="...">` blocks
3. Commit and push — GitHub Pages redeploys automatically within ~1 minute

### Updating the navigation

Navigation is generated by [`nav.js`](nav.js). To add or rename a top-level nav item or lifecycle stage, edit the relevant array in `nav.js`. Every page calls `renderNav()` with:
- `root` — relative path back to the site root (e.g. `'../'` for pages one level deep, `''` for `index.html`)
- `activeTop` — which top nav item is active (`'overview'`, `'use-cases'`, `'lifecycle'`, `'products'`, `'help'`)
- `activeSub` — which sub-tab is active (lifecycle stage or product category id)
- `pageNavItems` — array of `{ id, label }` objects for the right-side "On this page" nav

### Adding a new page

1. Create a new `.html` file in the appropriate folder
2. Copy the boilerplate from any existing page in the same folder
3. Update `renderNav()` at the bottom with the correct `root`, `activeTop`, `activeSub`, and `pageNavItems`
4. If the page should appear in the top nav dropdown, add it to the relevant items array in `nav.js`

### Updating the stylesheet

All styling lives in [`style.css`](style.css). It uses CSS custom properties defined at `:root` for all IBM Design tokens. Page-specific styles (e.g. the homepage hero) are written inline in `<style>` blocks within the page's `<head>`.

## How navigation works

`nav.js` renders three things dynamically on every page:

| Element | HTML id | Description |
|---|---|---|
| Top nav bar | `#topnav` | Blue bar: Overview, Use Cases, AI Lifecycle ▾, Products & Tools ▾, Getting Help ▾ |
| Lifecycle sub-nav | `#lifecycle-nav` | Dark bar below topbar, shown when `activeTop` is `'lifecycle'` or `'products'` |
| Page nav | `#pagenav` | Dark right sidebar: "On this page" scroll-spy links |

All internal links use relative paths. The `root` parameter in `renderNav()` is the relative path prefix that makes links correct from any directory depth:
- Pages at the root (`index.html`): `root: ''`
- Pages one level deep (`overview/overview.html`): `root: '../'`
- Pages two levels deep (none currently): `root: '../../'`

## Local development

No build step required. Open any `.html` file directly in a browser, or use a simple static server to avoid any browser cross-origin restrictions with local file paths:

```bash
# Python 3
cd ai-on-z
python -m http.server 8080
# then open http://localhost:8080
```

```bash
# Node.js (npx, no install needed)
cd ai-on-z
npx serve .
```
