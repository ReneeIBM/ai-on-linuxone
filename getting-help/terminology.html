AI on IBM Z

Terminology

A reference glossary of key terms used throughout the AI on IBM Z ecosystem — covering hardware, software, AI concepts, and IBM-specific product names.

Hardware & Platform

TermDefinition
IBM ZIBM's mainframe platform, encompassing the IBM z16, z15, and prior generations. Designed for mission-critical enterprise workloads at high availability and security.
LinuxONEIBM's Linux-only mainframe systems (e.g., LinuxONE Emperor 4, Rockhopper 4), optimized for open-source workloads and cloud-native deployments.
z16The current IBM Z flagship server (announced 2022), featuring the Telum I processor with an on-chip AI accelerator.
Telum IThe processor chip in the IBM z16 and LinuxONE Emperor 4 / Rockhopper 4. Includes an on-chip AI inference accelerator per chip, providing dedicated silicon for neural network workloads without requiring a GPU.
Telum IIThe next-generation IBM Z processor (powering IBM z17), with an enhanced on-chip AI engine offering greater AI compute throughput and support for additional neural network operations vs. Telum I.
IBM SpyreAn IBM PCIe accelerator card designed for LLM and generative AI inference on IBM Z, providing high-bandwidth matrix processing for large model workloads. Not a CPU — a discrete AI coprocessor.
s390xThe hardware architecture of IBM Z mainframes. Used to distinguish software packages compiled for IBM Z (as opposed to x86-64 or ARM).
z/OSIBM's proprietary operating system for IBM Z. It runs the vast majority of the world's large-scale transactional workloads including banking systems, insurance, and retail payment processing.
Linux on IBM ZLinux distributions (RHEL, SLES, Ubuntu) ported to the s390x architecture and running on IBM Z hardware. Most open-source AI/ML software on IBM Z runs on Linux on IBM Z.

AI & Machine Learning Concepts

TermDefinition
AI InferenceThe process of running a trained AI model on new input data to generate predictions or outputs. Contrasted with training, which adjusts model weights.
TrainingThe process of optimizing an AI model's parameters (weights) on labeled data using an algorithm such as gradient descent. Typically compute-intensive.
ModelA mathematical function (e.g., a neural network, decision tree, or regression) that maps inputs to outputs after being trained on data.
Deep Learning (DL)A subset of machine learning based on neural networks with multiple layers (deep networks). Used for image recognition, NLP, fraud detection, and more.
Large Language Model (LLM)A neural network with billions of parameters, pre-trained on large text corpora, capable of generating, summarizing, and reasoning over text. Examples: IBM Granite, Llama, Mistral.
Foundation ModelA large, general-purpose AI model pre-trained on broad data and fine-tuned or prompted for specific tasks. LLMs are one type of foundation model.
QuantizationA model compression technique that reduces the numerical precision of model weights (e.g., from FP32 to INT8 or FP16), reducing memory footprint and improving inference speed with minimal accuracy loss.
GPTQA post-training quantization method (W4A16 — 4-bit weights, 16-bit activations) widely used for compressing LLMs for efficient inference. Supported by IBM Spyre via vllm-spyre.
ONNXOpen Neural Network Exchange — an open standard format for representing AI models, enabling portability between frameworks (TensorFlow, PyTorch, scikit-learn, etc.).
PMMLPredictive Model Markup Language — an XML-based standard for representing traditional ML models (linear regression, decision trees, SVMs). Commonly used in z/OS environments via MLz.
MLOpsMachine Learning Operations — practices and tooling that automate the deployment, monitoring, and lifecycle management of machine learning models in production.
TensorA multi-dimensional array — the fundamental data structure in deep learning. Scalars, vectors, and matrices are all special cases of tensors.
TokenizationThe process of converting raw text into discrete units (tokens) that an LLM can process. A token typically represents a word fragment or subword.

IBM Z AI Products & Libraries

Term / AbbreviationFull Name & Description
zDNNIBM Z Deep Neural Network Library — a C library that exposes Telum AI accelerator operations to software. Version 1.0.x targets Telum I; 1.1.x adds Telum II operations.
zDLCIBM Z Deep Learning Compiler — compiles ONNX models to s390x binaries with automatic zDNN offload where supported.
RHOAIRed Hat OpenShift AI — a Kubernetes-native MLOps and AI platform running on Red Hat OpenShift, including on IBM Z.
Snap MLIBM Snap Machine Learning — an IBM library providing GPU-class acceleration for traditional ML training on IBM Z CPU hardware.
vllm-spyreIBM's fork of vLLM with a custom backend for Spyre accelerators, enabling LLM inference on IBM Z at scale.
TF ServingIBM Z Accelerated Serving for TensorFlow — production TensorFlow model serving optimized for IBM Z hardware.
TritonIBM Z Accelerated for NVIDIA Triton Inference Server — multi-framework model serving on IBM Z.

Architecture & Deployment Terms

TermDefinition
OpenShiftRed Hat OpenShift — IBM's preferred Kubernetes distribution for containerized workloads, including AI, on IBM Z and across hybrid cloud.
Tensor ParallelismA parallelism strategy that splits large model tensors (weight matrices) across multiple accelerator cards, enabling inference of models too large to fit on a single device.
Model ScoringRunning a deployed model against new input data to generate a prediction or score. Synonymous with inference in enterprise contexts.
Model DriftThe gradual degradation of a deployed model's accuracy over time as the real-world distribution of input data shifts away from the training distribution.
AI FactsheetA structured document (IBM terminology) that captures metadata, lineage, and governance information about an AI model throughout its lifecycle.
Hybrid CloudAn IT architecture combining on-premises infrastructure (e.g., IBM Z) with public cloud environments, connected by consistent tooling and APIs.
OpenAI-compatible APIA REST API interface that follows the same request/response schema as OpenAI's Chat Completions API, enabling drop-in compatibility with OpenAI client libraries.
