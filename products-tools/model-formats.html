Model Formats & Compilers

Before a model can run on IBM Z, it usually needs to be in the right format. ONNX and PMML are the two main interchange formats, and the IBM Z Deep Learning Compiler converts ONNX models into artifacts optimized for the Telum on-chip accelerator.

Converting Models to ONNX Format

ONNX (Open Neural Network Exchange) is a standard format for exchanging machine learning and deep learning models between frameworks. You can learn more about ONNX and how it is used with the IBM Z Deep Learning Compiler through the links below.

Converting or exporting trained deep learning models to the ONNX format is required when using the IBM Z Deep Learning Compiler on IBM LinuxONE.

The export process depends on the framework you use:

  • TensorFlow models can be converted using the open source tensorflow-onnx package.
  • PyTorch models can be exported directly to ONNX using PyTorch APIs.
  • Information about exporting models from other frameworks is available on the ONNX community page.

Best Practices

To avoid endian compatibility issues, convert models to ONNX on the same platform where they were trained. For example, if a model was trained on x86 hardware, convert it to ONNX on that x86 environment before transferring it to IBM LinuxONE.

When using the IBM Z Deep Learning Compiler, choose the ONNX opset version based on the supported opset levels listed in the Deep Learning Compiler documentation:

  • NNPA supported opset level
  • CPU supported opset level

For LinuxONE 4 and later systems, use the highest opset level supported by the NNPA operator support documentation. This typically provides the best compatibility and acceleration support.

Determining Which Operations Use the AI Accelerator

When compiling a model with the IBM Z Deep Learning Compiler, you can review how model operations are mapped. This helps you understand which operations run on the AI accelerator and which run on the CPU.

This information can be useful when evaluating model performance and identifying optimization opportunities.

  • Guidance on displaying model operation targets (CPU or AI accelerator)
  • Runtime instrumentation can be enabled to collect performance information
  • Additional performance guidance is available in the IBM Z Deep Learning Compiler documentation

Converting Models to PMML Format

PMML (Predictive Model Markup Language) is a standard format for exchanging and deploying traditional machine learning models. Models converted to PMML can be used with IBM Snap ML, and tree-based models can take advantage of IBM AI acceleration capabilities on IBM LinuxONE. PMML also provides a portable way to move models between training and deployment environments.

In LinuxONE environments, PMML is commonly used to deploy models trained with popular machine learning frameworks while maintaining portability and interoperability across platforms.

Generally, the best approach to converting models to PMML is to use sklearn2pmml. This allows you to create a PMMLPipeline object that can contain scikit-learn, XGBoost, or LightGBM models as part of a deployment pipeline.

Samples

For an example of converting a scikit-learn model to PMML, see the IBM Snap ML examples. One such example can be found here.

Additionally, here is a brief code snippet showing the process:

# Create a scikit-learn Random Forest Classifier model
model = RandomForestClassifier(n_estimators = 200, max_depth=6, n_jobs=4, random_state=42)

# Train a PMML pipeline that uses the scikit-learn model defined above
pipeline = PMMLPipeline([("model", model)]).fit(X_train, y_train)

# Save the trained PMML pipeline to a file, e.g., "model.pmml"
sklearn2pmml(pipeline, "model.pmml", with_repr=True)

Deep Learning Compiler for IBM LinuxONE

AI Lifecycle: Deploy Model

The Deep Learning Compiler for IBM LinuxONE is an enterprise-grade compilation framework built on open-source ONNX-MLIR (Multi-Level Intermediate Representation) technology. It converts open-format deep learning models (such as ONNX outputs from PyTorch or TensorFlow) into optimized C/C++ shared libraries specifically tuned for the IBM LinuxONE architecture.

Rather than interpreting model graphs at runtime, DLC compiles deep learning models into native binary representations. It applies low-level hardware optimizations, graph fusions, and quantization techniques while offloading mathematical execution directly to specialized on-chip accelerators—such as the IBM Telum Integrated Accelerator for AI (NNPA)—both in Linux and z/OS environments.

This gives business benefits of Ultra-Low Latency In-Transaction AI and Seamless Hardware Acceleration to customers.

Deploying ONNX Deep Learning Models on IBM LinuxONE Systems

ONNX is the Open Neural Network eXchange. You can read more about it here.

ONNX establishes a streamlined path to take a project from playground to production.

With ONNX, you can start a data science project using the frameworks and libraries of your choosing, including popular frameworks such as PyTorch and TensorFlow. The model can be developed and trained leveraging these frameworks on the training platform of your choice. Once the model is trained and ready to begin the deployment journey, you would export or convert it to the ONNX format.

Tools such as Netron allow inspection and exploration of an ONNX model. When it comes to running the model, there are various back-ends that can be used to test and serve ONNX models. This includes model compilers such as the IBM Z Deep Learning Compiler (zDLC), which is based on ONNX-MLIR.

The ONNX-MLIR project provides compiler technology to transform a valid Open Neural Network Exchange (ONNX) graph into code that implements the graph with minimum runtime support. It implements the ONNX standard and is based on the underlying LLVM/MLIR compiler technology.

The result of this compiler is a lightweight shared object library that has no dependencies on the framework or libraries that the model was developed and trained in. It can be used for inference from C++, Java, or Python programs.

IBM Telum Integrated Accelerator for AI

IBM Research enhanced the IBM Deep Learning Compiler to target the IBM Integrated Accelerator for AI for a variety of ONNX primitives. This support has been contributed to ONNX-MLIR, which is the foundation for the IBM Deep Learning Compiler. ONNX-MLIR has been updated to support IBM z17's new Telum II processor.

The IBM Deep Learning Compiler compiles ONNX models into optimized s390x binaries that automatically offload eligible operations to the Telum on-chip AI accelerator via the zDNN library — no manual mapping required. It is based on the open-source ONNX-MLIR project with IBM Research enhancements contributed upstream.

DLC is available as part of the AI Toolkit for IBM Z and LinuxONE, distributed through the IBM Z and LinuxONE Container Registry.

Key Capabilities

  • Produces a lightweight .so shared library with no framework dependencies at runtime
  • Supports encoder LLMs and small decoder LLMs (up to 2B parameters) on IBM LinuxONE 5
  • INT8 quantization, Layer Normalization, and GeLU support on Telum II (IBM LinuxONE 5)
  • Embeddable in applications or serveable via Triton Inference Server
  • C++, Java, and Python runtime APIs

Getting Started with the IBM Deep Learning Compiler

IBM LinuxONE users can use IBM Deep Learning Compiler through the Linux Container version.

  • Available through the IBM Z and LinuxONE Container Registry (ICR) listed under zDLC
  • Command-line model compiler that produces a .so library with optional Java and Python wrappers
  • Extensive details available in the IBM DLC official product page

These model libraries can be leveraged either directly or through Triton Inference Server, which is part of the AI Toolkit for IBM Z and LinuxONE.
